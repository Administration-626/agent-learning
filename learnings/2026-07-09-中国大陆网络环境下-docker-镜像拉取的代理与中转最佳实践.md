# 中国大陆网络环境下 Docker 镜像拉取的代理与中转最佳实践

Date: 2026-07-09
Agent: Antigravity

## 背景 (Background)
在中国大陆网络环境下，拉取 Docker Hub (`docker.io`) 或 GitHub Container Registry (`ghcr.io`) 的容器镜像时，常遇到网络连接重置或超时的问题（如 `i/o timeout`）。

## 问题 (Problem)
1. **终端代理不生效**：用户在终端配置了 `http_proxy` 等环境变量，但在运行 `docker compose up` 时，下载动作依然超时。这是因为 Docker 守护进程（Docker Daemon）是由 `systemd` 托管的系统后台服务，它在启动时无法直接读取或继承当前终端用户的 Shell 环境变量。
2. **国内公共源不稳定**：由于监管和流量压力，国内各大高校和云厂商的公共镜像加速器频繁失效或限制访问。
3. **认知误区**：部分初学者误认为利用阿里云镜像服务进行中转必须先购买阿里云服务器。

## 解决方案 (Solution)
1. **本地开发环境（配置代理服务）**：
   通过配置 Docker 守护进程的 Systemd 代理文件 `/etc/systemd/system/docker.service.d/http-proxy.conf`，将本地或局域网的代理地址和端口显式配置给守护进程：
   ```ini
   [Service]
   Environment="HTTP_PROXY=http://<proxy-ip>:<proxy-port>"
   Environment="HTTPS_PROXY=http://<proxy-ip>:<proxy-port>"
   Environment="NO_PROXY=localhost,127.0.0.1"
   ```
   配置完成后，需要重载并重启服务：
   ```bash
   sudo systemctl daemon-reload
   sudo systemctl restart docker
   ```
2. **无代理的服务器/生产环境（镜像中转方案）**：
   利用 GitHub 境外通畅的网络，通过 GitHub Actions 写一个工作流脚本，自动将官方镜像（如 `ghcr.io/immich-app/immich-server:v3`）拉下来，并重新推送到免费的**阿里云容器镜像服务 (ACR) 个人版**中。服务器端只需要直接拉取这个阿里云上的个人私有镜像即可，既稳定安全，又不需要在服务器挂代理。

## 避坑指南 (Pitfalls)
1. **阿里云镜像服务是免费的**：使用阿里云个人容器镜像服务 (ACR) 并不需要购买阿里云服务器，它是一个独立的、免费向所有开发者开放的容器镜像网盘。
2. **不要混淆 APT 源与镜像源**：
   * **APT 软件源**（如官方在 `/etc/apt/sources.list.d/docker.sources` 配置的内容）：用于安装或更新 Docker 软件本身。
   * **Docker 镜像源**：用于拉取运行时的容器镜像（如 Postgres, Valkey）。配置 APT 源无法解决拉取容器镜像超时的问题。
